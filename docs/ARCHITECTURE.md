# Архитектура Numina

Numina намеренно построена как маленькое офлайн-приложение без DI-фреймворков, webview, сетевого слоя и production-зависимостей. Это уменьшает размер, поверхность атаки и вероятность supply-chain проблем.

## Слои

```text
MainActivity (UI, lifecycle, accessibility)
        │
        ├── CalculatorState (редактирование и состояние сессии)
        │         │
        │         └── ExpressionEngine (tokenizer/parser/evaluator)
        │                   └── NumberFormatter
        │
        └── HistoryRepository
                  └── PreferencesHistoryRepository (локальное хранилище)
```

### Domain

`ExpressionEngine` — рекурсивный descent parser, не выполняющий скрипты, reflection или динамический код. Он нормализует безопасный набор математических символов, разбирает выражение и возвращает типизированный `EvaluationResult` с `EvaluationError` вместо необработанных исключений.

Основные ограничения защиты от злоупотребления:

- максимум 512 символов в выражении;
- максимум 64 уровня вложенности;
- максимум 4096 операций разбора;
- факториал только для целых значений 0–170;
- явная проверка деления на ноль, области определения и конечности результата.

Приоритеты соответствуют привычной математической записи: степень правоассоциативна, а `-2^2` вычисляется как `-(2^2)`. Проценты контекстны для сложения/вычитания и относительны для умножения/деления.

`CalculatorState` отвечает за безопасное редактирование выражения, live preview, результат `Ans`, знак, скобки и переходы после `=`. UI не знает грамматику выражений.

### Data

`HistoryRepository` отделяет домен от хранилища. Реализация на `SharedPreferences` хранит до 50 записей, использует Base64 для полей и пропускает повреждённые записи. История не входит в Android backup; пользовательские настройки входят в явный allowlist.

### UI

`MainActivity` создаёт framework View hierarchy программно. Такой выбор исключает runtime UI-зависимости и сохраняет полный контроль над Android 6–17. Экран поддерживает edge-to-edge, safe insets, аппаратные клавиши, accessibility descriptions/live region и compact-height layout.

Тема применяется в `attachBaseContext`, чтобы ресурсный `uiMode` был установлен до `onCreate`. Это гарантирует корректные `values-night` даже при принудительном выборе Dark на светлой системе.

## Поток вычисления

```text
Нажатие/клавиатура → CalculatorState → ExpressionEngine
                                  ├── успех → formatted preview/result
                                  └── ошибка → локализованное безопасное сообщение

Успешное «=» → Ans + HistoryRepository → обновление UI/accessibility
```

## Данные и доверительные границы

- пользовательский ввод считается недоверенным и проходит только через ограниченный parser;
- файлов, сети, IPC API и WebView в вычислительном пути нет;
- экспортирована только launcher Activity; внешние произвольные intent payload не принимаются;
- секретов, токенов и персональных данных приложение не запрашивает.
